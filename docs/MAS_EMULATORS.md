## 2. ADB 端口规律与漂移史（本档案的重点）

> **2026-09-28 起，本节结论以 `docs/MAS_PORT_RULES.md` 为准**（含 idx27 改口的更正 + 现取决窍 + 逐台实测表 `runtime/reports/mapping.md`）。本档案保留 09-27 普查原貌。

### 2.1 实测规律（逐台核对过 55 台）

| 家族 | 适用范围 | adb 口（vm_config 持久化值） | 本次核对 |
|------|----------|------------------------------|----------|
| A | idx 0–31 | `16384 + 32×idx` | ✓ 全部吻合 |
| B | idx 32–60 | `16388 + 32×(idx−32)`（**= 旧公式 −1020**，33 台逐台一致） | ✓ 全部吻合 |

- **副口**：每台运行时还有一个 guest adbd 转发口 `5555 + 2×idx`（三次快照全部实录：idx13→5581、idx24→5603、idx54→5663、idx56→5667…）。**MAA 用的是主口**（asst.log 实测 `-s 127.0.0.1:16800` 等 vm_config 值），副口是天然备用端点（同实例，两个口都通）。
- 家族 B 的实证偏差样例：idx54 旧公式 18112 **实际 17092**（真在跑，快照实录）；idx56 旧公式 18176 **实际 17156**（MAA_4 的 gui.json 现存连接地址就是 17156）。
- 家族分界与**创建时间无关**（idx48 创建于 02-18 属 B 族；idx31 创建于 09-21 属 A 族）⇒ 可信的解释是「分配批次/槽位」而非时间：疑似 MuMu 内部槽位在生成 33 个以上 VM 时以 +4 偏移重置序号（+4 = 16388−16384）。**不要试图推算 idx≥61**，现查为准。
- 端口来源 = `vm_config.json` 的 `vm.nat.port_forward.adb.host_port`，**持久化在实例上**：同一实例重启不改口（三次快照 20 分钟内完全一致；09-27 全天 asst.log 与今天端口全部吻合）。**漂移实际发生在「实例重建/重命名/重编号」时，而不是每次重启**——旧的「重启就漂」说法在这台机上要修正为「重建就漂」。
  - **2026-09-28 更正（任务 `t_ee50913f` 只读实测）**：**至少一例反例**——idx27（官-12／槽位 MAA_12）**未重建**（`extra_config.createTime` 仍是 2026-01-21），但 adb 主口 **17248 → 17249**（`vm_config.json` 07:57:24 落盘，MAA 07:58:30 连新口）。所以更准的口径是「**启动时可能改口（顺延），执行前现查为准**」。端口规律与新表请看 **`docs/MAS_PORT_RULES.md`（权威）**，逐台实测值在 `runtime/reports/mapping.md`（`tools/mas_mapping.py --build` 生成，可 `--verify` 查漂移）。
