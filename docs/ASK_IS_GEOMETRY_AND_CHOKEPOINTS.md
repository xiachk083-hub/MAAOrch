## 3. 问题 B：堵点排序要不要、以及怎么引入"人"

**现状**（纯几何，只看路）：对每个**可部署**格

```
score = Σ 敌人数 / (1 + 离防守点的剩余步数/6)  ×  (1 + 0.25 × (经过它的不同路线数 − 1))
```

外加两条硬约束：**只排可部署格**（不可部署的格放不了人 ✗）、**排除离任一刷新点 ≤2 步的格**（门口不设防 ✗）。
分 BLK（自己就在路线上 ⇒ 能阻挡）/ ADJ（紧邻路线 ⇒ 能打到，权重 0.6）。实测把"门口格"从 41/48 降到 15/43 ✓。

**问题**（请给可执行方案，别给泛泛建议）：
1. 要把它做成"能不能守住"，最小充分的模型是什么？我们有算子库（职业/费用/射程格数可从关卡数据取），但没有 DPS/血量对抗模型。
2. "瓶颈"是否该用**网络流/最小割**这种正式工具？若是，图怎么建（节点=可部署格？边=路径相邻？容量=敌人数？），输出怎么读？
3. 有没有"**别过度工程**"的判据 —— 什么信号出现才值得上更重的模型？
