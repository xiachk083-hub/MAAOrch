# AI 打关的路线选择与取舍（对照"三步走"方案）

> 2026-09-16 立项。用户提供了一份通用"三步走"计划（RL / IL / VLM + MAA 环境 + 数据管道）。
> 本文件把它的每条建议落到"我们采不采纳、为什么、什么时候做"。
> 配套：`docs/CLEARING_AGENT.md`（架构）、`docs/AGENT_ACTION_MAP.md`（动作/流程）、`docs/SKILL_EMULATOR_OPS.md`（操作技能）。

## 1. 结论先行

**起点不是模型，而是执行链。** 2026-09-15 整晚实战，卡住的每一次都不是"AI 不够聪明"：

| 现象 | 根因 | 层 |
|---|---|---|
| 点节点没点开却照样起 MAA | 缺导航后置校验 | 工程 |
| MAA 把我们打开的关卡页按返回键关掉 | 双向控制冲突（StartUp） | 工程 |
| 详情页/编队页判成同一页 | 模板重叠 | 工程 |
| MAA 编队后自己退出，没人读报错 | 报错未读 | 工程 |
| 画面一直暂停、谁都不动 | 等待无界、无超时兜底 | 工程 |
| 方案里塞进精0Lv1 干员 / 非法格 | 缺前置校验 | 工程 |

RL 学不会这些、IL 录不到、VLM 看不出来。那位 UP 自述"不是全自动、很多 engineering"、
另一个 agent 花 2 小时沉淀"模拟器操作 skill" —— **证据一致：值钱的是操作技能层**。

## 2. 逐条取舍

| 建议 | 我们的判断 | 说明 |
|---|---|---|
| 用 MAA 做交互底座 | ✅ **已在用** | 截图/任务调度/作业执行都能复用；注意它的边界（命令行不导航、有 StartUp 会抢页面） |
| AITK / Mobile-Env 作为备选 | ⛔ 暂不引入 | 我们的执行环境是 MuMu + adb + MAA，换底座成本高、收益低 |
| OpenCV 预处理 + YOLO/Tesseract 识别 | ✅ **部分已用** | OpenCV 模板匹配（状态判别 7 态）、PaddleOCR（MAA 自带）+ MAA OperBox；**敌人检测**暂不做（我们用官方关卡数据替代：波次表 + 敌人数值） |
| adb input tap / keyevent 执行 | ✅ **已用** | `AdbScreen` + `services/ai_agent/actuator`（点击→验证→留证） |
| **RL（Arknight-Agent 多头 DQN）** | ⛔ **不作为起点** | 没有游戏内状态接口，只能截图 → 样本效率极低；"自定义模拟器提速 50–100×"是另一个工程量级。作为长期研究可看，不作为打关能力的地基 |
| **IL（模仿学习）** | ⚠️ **有更便宜的数据源** | 作业站的 copilot 作业 = 人类打法的**结构化记录**（站位/朝向/时序/技能），我们已能自动筛选/验证/改招 → 零成本拿到 IL 数据管道，不必录屏标注 |
| **VLM（Lumine / CombatVLA）** | ⚠️ **后置** | 它解决"决策与泛化"，我们缺的是"执行可靠"；现在上 = 给没装好轮子的车换引擎。等执行链稳、单关能无人干预打通后再谈 |
| 奖励设计 / 训练效率 | ⛔ 暂不涉及 | 同上 |

## 3. 我们采纳的路线（混合）

```
① 世界模型算打法   地图 choke/路线数/波次时间表/敌我数值 → 站位·朝向·分工   [已有：stage_value.py / derive_plan.py]
② 可靠执行         MAA 跑作业 json（编队+开打）或执行器逐动作；每步验证    [已有：clear_runner.py + MAA]
③ 状态机兜底       7 态判别 + 有界自愈 + 超时解除暂停 + 每步写明原因       [已有：screen_state.py + clear_runner.py]
④ 决策            规则优先（费用/技能就绪/波次表），LLM 只兜底            [待建]
⑤ 迭代            失败→归因（漏怪/输出不够/练度/格子冲突）→改招→重跑      [已有雏形：plan_loop.py ledger]
```

## 4. 立即要做（今晚最后的发现，按优先级）

1. **读 MAA 报错原文**：`asst.log` 的 `SubTaskError` details 直接打印到循环日志（多次"卡住"其实 MAA 明说了原因）；
2. **格子合法性校验**：方案里的位置只能取自地图 `buildableType==1 && heightType==0 && 未被占用`；朝向要合法；
3. **方案合法性校验**：编队人数上限、每个干员的技能序号存在性、精0Lv1（4★+）排除（已修一条）；
4. 上述三条落地后再跑 EX-2（v3 已生成但含非法格/未复核，先别用）。

## 5. 长期（等执行链稳了再评估）

- **IL**：把作业站作业当"人类打法语料"，做策略先验（不需要录屏）；
- **VLM/LLM**：做跨关/跨游戏泛化与异常处理（如同那位 UP 的"每轮读画面重新决策"）；
- **RL**：只在能拿到**快速环境**（自定义模拟器或官方接口）时才值得投入。
