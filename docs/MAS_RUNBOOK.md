## 0. 一句话模型

```
产能（号/班） = 跑位数 × 班次时长 ÷ 单项时长
每号每天      = 2 轮 × 37 分 = 74 分
成本          = 机器折旧 + 电费 + 人工
规划余量      = 时间留 30%、磁盘留 20%
```

- 单项时长 37 分 = 任务 29.5 分（基建 12.7 / 理智 7.3 / 唤醒 3.9 / 信用 3.6 / 公招 1.3 / 领奖 0.7）+ 固定开销 6~8 分。
- 硬件成本摊到每号每月约 **¥2**（¥4,000 机器 ÷36 + 电费 ~¥80 ⇒ ¥191/月 ÷ 87 号）⇒ **硬件可忽略，人工才是大头**。省钱要省人工。
- 单槽成本：CPU ≈1 核、内存 2.5~4G、显存 ~350MB、磁盘 28G/号（官服合并后仅 ~2.8G/号）。

### 产能对照（两班制、每号 1 轮/班）

|---|---|---|---|
| 8 | 48%（实测） | 37 分（实测） | 58 |

**下一个要看的数**：明早的**单项时长**（>42 分＝到拐点）与 **CPU**（估 ~72%）；看板「🏭 产线状态」会自动显示 24 条队列的进度。

## 2. 接号 SOP（onboarding）

1. **实例**：官服 → 可 10 个号共用一台实例（游戏内账号列表上限 10）；**其他服（B/日/台）→ 一号一台**（切号不可靠）。
2. **AUTO-MAS**：建 script（名字 = 明日方舟-<服>-<编号>）+ 加 user，**必须录 Id/Password**（没密码的号不能自动切号，只能独占实例）。
3. **绑定**：`Emulator.Index` = 该号实例号；`Info.Path` = `E:\MAA-Multi\MAA_<槽位号>`。
4. **入队**：同一个 script 的多个号会**串行**跑；维持「每槽 4~5 个号」。
5. **验收**：跑一局看 AUTO-MAS 日报标题 —— `09-21 |√| 某某 的自动代理统计报告` 为成功、`|X|` 为失败。
6. **记账**：号名 / 服 / 实例号 / 槽位 / 有效期 / 备注 —— **只记账号本身的属性**；归属、结算这类信息不进工具。

**推送渠道**：日报默认推 **Discord webhook**（正文摘要 + 完整日报作为 `.md` 附件），未配置时回退本机气泡通知。

`notify_on`：`abnormal`（默认，只在有失败/未跑时推）/ `always`（每班都推一条全绿）。
连通性自测：`python tools/mas_watch.py --test-notify`。

手动兜底（想自己看一眼时）：

| 看什么 | 一键命令（主机上） |
|---|---|
| 失败 / 没跑的号 | `python E:/_mas_fail.py` |
| 各队列收工与离散度 | `python E:/_mas_shift.py daily`（晚班用 `evening`） |
| 总览看板（跑/成/败、剿灭、耗时） | `python E:/mas_dashboard.py --days 1` |

### 看板（2026-09-21 上线）：产线状态页

不想开终端时的入口：**就在这台机器（desktop-l1oemr3）上，浏览器直接开 `http://127.0.0.1:19999/`** → 侧栏「🤖 auto-mas」→ 页签 **🏭 产线状态**。

⚠️ 两个坑（都踩过）：
1. **它是会话绑定的**：曾经用「后台任务」起，会话一结束进程就没了 —— 打开是空的，还容易误判成"链接是别人机器上的"。现在以脱离会话的独立进程跑（PID 用 `Get-NetTCPConnection -LocalPort 19999` 的 OwningProcess 核），开机自启走启动文件夹的 `MAAOrch-看板.bat`。**打不开先查进程在不在，别怀疑地址。**
2. **跨设备访问要绕过系统代理**：`tailscale serve --bg --https=8443 http://127.0.0.1:19999` 已挂上（443 那条留给 DSH 本体，别动），但本机 Chrome 走 Clash 系统代理，而 `ProxyOverride` 里没有 `*.ts.net` / `100.*` ⇒ ts.net 域名会被丢给代理节点、报 `ERR_CONNECTION_CLOSED`；`curl` 这类不走系统代理的客户端则直连 200。要真正跨设备用，先把 `*.ts.net` 加进代理绕过（或改挂到 443 的 `/mas` 路径下）。

新浏览器首次要先在「⚙ 设置」点一次保存（token 会从配置预填，只是同步进 localStorage），否则 `/api/*` 全是 401。

数据由本地后端 `GET /api/mas/status`（聚合在 `services/mas_l3.py`）给，三个来源：
**主机实时快照**（SSH：在飞 MAA / 盘位 / 各队列进度 / 今日失败 / 未跑）＋ **AUTO-MAS 近 7 天历史** ＋ **本地留痕**（日报 `latest.md`、台账 `mas_ledger.jsonl`）。

页面就回答四个问题：**今天跑成什么样**（一次过 / 补跑成功 / 全败 / 尝试次数 / 首末时间）、**有没有要我动手的**（失败明细 + 一键补跑 + 未跑名单）、
**是不是只有今天这样**（近 7 天趋势 + 失败原因 Top + 钉子户）、**机器还撑得住吗**（盘位告警线 + 队列进度条）。

| 动作 | 接口 | 底层 |
|---|---|---|
| 看状态 | `GET /api/mas/status?days=7[&refresh=1]` | SSH 快照（45s 进程内缓存）+ `/api/history/search` |
| 补跑失败号 | `POST /api/mas/rerun` `{"accounts":[…]}`（空 = 取快照里的失败号，≤8 个） | `tools/auto_mas_rerun.py --apply`（后台线程，页面显示进度） |
| 清临时队列 | `POST /api/mas/cleanup` | `tools/auto_mas_rerun.py --cleanup` |

统计口径（与日报一致，别记混）：**一次过** = 当天全部尝试 DONE；**补跑成功** = 先 ERROR 后 DONE；
**全败** = 当天最后一次尝试仍是 ERROR。

运维要点：`/api/*` 需 token（页面在设置页填，值同 `models/config.json` 的 `api_token`）；
启动 `tools/mas_web_ui.bat`（登录自启副本 = 启动文件夹里的 `MAAOrch-看板.bat`）；
**改完 `ui/web/*.js` 必须同时改 `ui/web/index.html` 里该脚本 `?_v=` 的版本号**，否则浏览器吃缓存看不到改动。

## 5. 失败处理 SOP

**自动（已上线）**：
```
MAAOrch-MasWatch（每 20 分钟）
  → 班次收工（连续两次 0 个 MAA）→ 出日报
  → 日报里若有 |X| → 自动调 tools/auto_mas_rerun.py 建临时队列补跑
  → 同号每天最多补 1 次（防抖）· 单批最多 8 个 · 全过程写 mas_ledger.jsonl
```
**手动兜底**：`python tools/auto_mas_rerun.py --accounts "号1,号2" --apply`；跑完 `--cleanup`。

| 报错 | 大概率原因 | 对策 |
|---|---|---|
| 模拟器启动失败 | 实例级故障（VM 进程起但 Android 不 boot） | **迁号**：改 `Emulator.Index` 到能用的实例 + 按「同 emu 同槽位」重排 |
| MAA 进程超时 | 该号/实例偶发拖慢（日服高发） | 重跑；连续多天则查实例；必要时给该服降并发 |
| MAA 部分任务执行失败 | 卡在某个界面（弹层/登录态） | 重跑；仍失败看 MAA 日志里第一个 `任务出错:` |
| 未能正确登录 PRTS | 服务器侧不稳（日服实测） | 重试通常能过 |

纪律：**同一台模拟器绝不允许两个 MAA 同时跑**（曾出过假数据）。

**满足任一条就下单**（硬件 3~4 天到货，不必提前占资金）：

2. **产能**：现有机器到了拐点（**单项时长 > 42 分**）且 12 槽的 ~87 号也不够；
3. **冗余**：不能接受「一台挂全线停」。

**买 → 买同款二手平台（¥4,000 / 2TB）**；按对数规律，**两台 12 槽 > 一台 16 槽**，且互为备份。

## 8. 红线与纪律

1. **禁止用 adb+root 读写游戏客户端私有数据**（`/data/data/...shared_prefs`）—— 封号风险，代肝号封了是事故。信息只能走 MAA 的正常自动化路径（点屏幕/截图/OCR）。
2. **改配置前必备份**；实验脚本一律放 `runtime/`，跑完 `--cleanup` 清残留（临时队列、改过的实例设置）。
3. **判定"这班跑完了"要连续两次（间隔 3 分钟）检测到 0 个 MAA 进程** —— 队列换项空隙里也会短暂为 0。
4. **MMuMu 实例保持**：`max_frame_rate=60`（MAA 硬要求，降帧实测会把任务跑死）、`renderer_mode=dx`、`renderer_strategy=perf`、`root_permission=false`。
5. 搬迁/配平类工具必须对"空槽位"有兜底 —— 曾差点把脚本 `Path` 写成空字符串直接废掉脚本。

## 9. 分层与 MAAOrch 的定位（2026-09-21 定）

```
L4 人工层   账号接入与归属 · 续期 · 风险判断（买不买机器）        ← 只有人能做的，不进工具
L3 工作流层 MAAOrch：台账 · 接号 · 排班与容量 · 监控告警 · 失败补跑 · 备份 · SOP
L2 执行层   AUTO-MAS：队列 · 起模拟器 · 跑 MAA · 重试 · 原生日报
L1 设备层   MuMu 实例 · 游戏客户端 · MAA（含账号登录）
```

**分工原则：MAAOrch 只管 L3，不重造 L1/L2 的轮子。**
- 与 L2 的接口只有三个：AUTO-MAS 的 HTTP API（`queue/*`、`scripts/*`、`history/search`、`dispatch/start`）、主机文件（`history/`、`config/`）、SSH（进程/实例/磁盘）。
- 与 L1 的边界是红线：**不 root、不读游戏客户端私有数据**，信息只走 API / 文件 / MAA 的正常自动化路径。
- **形态定位（2026-09-21 用户拍板）**：它就是一个「技术力很强的多开日常工具」—— 形态、术语、界面都按“自己有一堆账号、自己清日常”来写；**不做平台化、多人协作、计费、客户门户**这类明显商业化的东西。**但能力不打折**：并发编排、监控、补跑、台账该有都有 —— 只是表现得不像个"业务系统"。

### 该保留 / 该冻结 / 该新建
| 处置 | 内容 |
|---|---|
| **保留（L3 已有资产）** | `tools/auto_mas_flatten.py`（按 emu 组配平）、`auto_mas_add_slots.py`（扩跑位）、`auto_mas_rerun.py`（临时补跑）、`auto_mas_queue_times.py`、主机侧 `_mas_fail.py` / `_mas_shift.py` / `mas_dashboard.py`、本 RUNBOOK |
| **冻结/归档（当年为"自己驱动 MAA"写的，现由 AUTO-MAS 承接）** | 自研 scheduler / runner / dispatch_pool / launch_queue 那一摊；肉鸽 `fz-maa` 自启链路（已 Disable）；一切"MAAOrch 自己起 MAA 跑日常"的路径 |
| **新建（工作流层的四个闭环）** | ① 日报+告警（观测）② 失败自动补跑（动作）③ 接号 onboarding（入口）④ 账号台账 SQLite + 有效期提醒（记账） |

### 判据（以后拿不准某件事该不该做）
> 这件事是"让机器多干活"还是"让人少干活"？
> - 让机器多干活 → 属于 L1/L2，**交给 AUTO-MAS 或买机器**；
> - 让人少干活 → 属于 L3，**MAAOrch 的活**。

## 10. L3 质量基线（"最优"的可验收定义）

> 原则：**不商业 = 只约束表现层**（术语 / 界面 / 文档不像业务系统）；**能力层与工程层必须最优**。
> 不为"看起来不像业务"而砍功能，也不为"功能强"而长出商业化形态。

| 环节 | "最优"的判据 | 可验收指标 |
|---|---|---|
| **接号** | 一条命令跑完，且**自动校验**每一步（凭据、实例、Path、入队、验收） | 接号 ≤ 5 分钟；**零遗漏**（尤其 `Password` 非空，否则该号不能自动切号） |
| **排班 / 容量** | 按曲线拐点排、留 30% 时间 + 20% 磁盘余量；改动**不动在飞任务**（快照语义） | 单项时长 ≤37 分（**>42 分即告警**）；槽位利用率 ≥70% |
| **监控** | 每天**一条消息**，只在异常时响；必含三数：失败名单 / 没跑名单 / 单项时长 | 异常发现 ≤1 个班次；误报 0（平时静默） |
| **失败补跑** | 观测→决策→动作→留痕**全自动**；同号每天限补 1 次（防抖） | 漏跑 = 0；补跑成功 ≥90%；每次补跑记录原因 |
| **账号台账** | **单一真相源**，且能跟 AUTO-MAS 实际配置**自动对账** | 对账差异 = 0（脚本化检查）；号 ↔ 实例 ↔ 槽位 一一对应 |
| **备份 / 回收** | 周期化导出 + **演练过恢复**；退役四步有记录 | 每周 export；恢复演练每季度 1 次；每台腾出空间有账 |
| **工具纪律**（所有脚本） | dry-run 默认、`--apply` 显式生效、**幂等**、**可回滚**、支持 `--json` | 改动前必有 `.bak`；重复跑结果一致；报错要能定位到具体脚本+行 |
| **判据自洽** | 验证者与被验证者**共享同一判据**；**报告与行为同源**（顺序、uid 一律回读，不靠推断） | 工具能自己回读并证明"确实生效了" |

### 工程纪律（这几条是踩过坑换来的，写死）
1. **只读优先**：默认 dry-run，`--apply` 才写；写前必备份。
2. **幂等**：任何迁移/配置脚本重复执行不产生额外变化。
3. **空闲判定**：连续两次（间隔 ≥3 分钟）检测到无 MAA 进程才算"跑完"。
4. **同一实例绝不允许两个 MAA 同时跑**（曾造成假数据）。
5. **对空/未初始化状态必须有兜底**：绝不让"取不到"退化成"写空值"（曾差点把脚本 `Path` 写成 `""`）。
6. **日志即证据**：判断在飞看 `MAA_N\debug\gui.log`，判断成败看 `E:\AUTO-MAS\history\<日期>\<账号>\*.json` 的 `maa_result`。
