**投影是"透视"，不是仿射 —— 别用基向量外推格子**（2026-09-19 实测，我在这上面翻过车）：
`project()` 在 **(0,0) 处的局部差**是列 **(+84,+22)**、行 **(−13,+61)**（1280 系，×1.5 得设备像素），
但实测 `project(2,2)=(475,256)`，而按这两条基外推是 `(470,276)` —— **差 20px，格数越多偏得越远**。
⇒ **任何"基向量 × 格数"的线性公式都是错的**（我照它画了一版四边形，被用户当场看出歪："这次不就是透视了一下吗"）；
**逐格调 `project()` 才是对的** —— 点+线的标法正是这么来的，所以它严丝合缝。
（局部导数只当"半格容差"用还行：约 ±65px / ±47px，见下面的落点精度段。）
- `buildable==1` → **地面可放**（绿点，PA-1 = 18 格）
- `buildable==2` → **高台可放**（青点，PA-1 = 7 格）；⚠️ 这些格 `walkable=0`（**敌人不走高台**）⇒ 用 `if not walkable: continue` 会把这 7 格全漏掉（我漏过一次）
- 其余 → **不可放**（白点，PA-1 = 38 格 = 63 格网格减掉上面两类）

- **点手牌（选牌部署态）⇒ 镜头拉近**：缩放 **×1.24~1.30**、旋转 **+5~7°**、平移 **(−226,−149)px**
  ⇒ 此时按关卡投影算出的格心**是偏的**，必须 `Hinv·project(cell)` 搬过来（`annotate_live.py --ref <同一局的普通视角帧>` 会自动求）。
- **点场上干员（看它的 UI）⇒ 镜头不动**：配准 ×0.996、旋转 −0.3°、平移 0 ⇒ 格网照用投影即可。
- ⇒ 结论：**要下牌时算落点，必须按"选牌态"的视角算**；这就是用户说的"部署是偏移的"。

**战场中干员的 UI（用户点名要看的一组，`annotate_live.py` 的 F1~F12）**：左侧详情面板（名字/LV/ATK/DEF/BLK/攻撃範囲 标签/
HP 数字+血条/技能·特性·素質 页签/技能图标/技能名+标签行/技能说明）＋地图上（技能按钮圆钮/充能绿条/充能计数 `14/78`/撤退 ✕）。
⚠️ 撤退 ✕ 是**深色符号画在浅色方牌上** ⇒ 固定亮度阈值抓不住，用**自适应阈值找浅色方牌**（已在 `_plate()`）。
⚠️ **攻击范围菱形故意没量**：细线、亮度和 `PAUSE` 大字一样，阈值分不开 ⇒ 要它得按干员数据里的 range 算格子，别拿像素猜。

**落点精度 = 半格，且两条基都不与屏幕轴平行**（用户 2026-09-19 点出的"有时候放不精准"的来历）：
列基 **(+126,+33)**、行基 **(−19.5,+91.5)**（设备像素）⇒ 目测"看着在格子上"≠"坐标是格心"。
容差就是半个格子：**沿列 ±65px、沿行 ±47px**，超出即串到隔壁格；而相邻格心在屏幕上只隔 **130 / 94px**。
**规矩：落点一律用 `project()` 算出的格心**（`battle_loop.deploy()` 已如此），**不许按画面估**。
配套守卫：循环落错格时会报出"最近的自己人在 (x,y)（差 n 格、屏幕 xx px）"，把"差一格"和"压根没放下去"分开。
。其中 13 格是**敌方路径**（`walkable=1`，敌人从这走）——
  画法上没单独区分（用户认可的那版就是三色点）；要判"敌人会不会经过"用 `walkable`，别用颜色。

## 4. 开打前/中的硬规矩（今晚踩过）

1. **单一控制者**：要么 MAA，要么 agent，二选一。开跑前确认另一方已停（今晚两只手互抢 → 反复选人 + 卡死）。
2. **绝不用 `nohup … &` 起常驻驱动**：父进程被杀子进程不死 → 堆积 19 个 python → CPU 拉满。要常驻就一个进程、退出带走子进程。
3. **不盲等**：用状态变化驱动（≤1s 反应）；失败/结束立刻处理。
4. **不重复点同一坐标**：点节点只在"地图 → 关卡页"这一次跳变上做。
5. **失败返还理智** → 迭代便宜；但**没实测过的方案优先演习**（演习 = 零理智，MAA 不接管，需人/agent 自己打）。
6. **拖拽只能用「慢滑」**：`input swipe` 时长给 400-600ms。**快滑和 `input tap` 游戏都不认作「放置」**——`tap` 只对菜单按钮有效（节点/演習/行動開始/暂停都行），拿卡放人必须慢滑（MAA 走的是 MiniTouch，和这条是两回事）。
7. **定朝向那一次滑动会把干员平移**：实测向左右滑 600px，干员从 `(4,3)` 一路跑到大约 `(2,3)`。⇒ 朝向滑动**距离要短**，别把 MAA 的 `400×(屏高/720)` 直接套上来。
8. **部署成没成，用三条独立信号一起判**：`残り配置可能数` N→N-1、**费用**减掉该卡费用、**卡排张数** −1。只看画面里"有没有人"会误判（暂停时人体可能被 `PAUSE` 大字盖住，只剩血条和朝向箭头）。
9. **放人用本地投影，别目测**：`tile_map.load_level(stage)` + `level.project(col,row)` → ×1.5 → 两段慢滑。今天目测两次全落空，用投影一次成。
10. **暂停帧上数「我方干员」用血条颜色找**（ONNX `operators_det` 在压暗帧上检出 0）：阈值 `(B-R)>25 & (G-R)>10 & B>90`，再做 3×9 闭运算 + 连通域过滤（宽≥70、高 6~26、面积≥400）⇒ PA-1 暂停帧上**恰好 2 条、零假阳**（实测；血条尺寸固定 125×7）。
11. **卡排会随张数重排**：右对齐只是近似——部署掉一张后其余卡的 x 会变（实测 11 张时最左图标 x=64，掉一张变 10 张后最左图标 x=206）⇒ **每次部署前重新用职业图标模板测一遍卡位**，别复用上一帧的坐标。
12. **远程干员只能放高台**：往地面格拖远程（狙击/术师/医疗/辅助）游戏直接取消（画面无变化、不扣费用）。`tile_map` 的 `buildable==1`=地面、`==2`=高台，按卡上的职业图标选格。
13. **顶部敌计数「x/y」别用 OCR 认**（2026-09-19 实测）：暂停/演习态的**艺术字体 + 红色「演習中」条**会把 `0/19`
    读成 `盛〇/79`、`（盘o/7Z`（ROI 换四处、阈值降到 0.2 都一样）。要认"这是哪一关"改用**画面指纹**：
    在本关可走格的投影点上各采一小块颜色均值 → 得到一个向量，同局差 ~2、换关差 ~42 ⇒ 拿它当身份/接管检测。
15. **"慢滑当点击"会被当成"长按"**（2026-09-19 实测踩到三次）：`input swipe x y x y+3 500` 用来点按钮，
    在**有长按语义的 UI 上会触发长按动作** —— 实测把大厅的合成玉计数器点成了「源石换合成玉」确认框、
    把理智面板点成了「用回复剂恢复 80 理智」框（两者**都会消耗资源**，必须当场 ✕ 取消）。
    ⇒ **菜单类按钮用 `input tap`**（短促 ✓）；只有"暂停态的战斗内按钮"实测需要长按形式的慢滑（见下条历史记录）。
    另：**设置页右上角是「リセット」**（重置）—— 返回导航时别把点击落到 (25,30) 的齿轮上，宁可多按几次确认画面。
16. **卡排可能被收起**（2026-09-19）：实测碰到一个战斗中**底部没有干员卡行**的局（同早先 rl_long 那批帧）——
    没卡排就**无法下干员**（没东西可拖）。且此时用低阈值找职业图标会冒出**间距毫无规律**的伪命中 ⇒
    卡排检测**必须同时校验"等距"**（1080p 步距 ~164px），只数个数会**假通过**（假通过比没有更危险）。
14. **绝不"贴到屏幕上的任意一局"**（单一控制者）：循环/脚本默认必须带**参照指纹**（`--expect-fp`），
    没有就拒绝跑。实测这台机上当时正跑着**别人的关**（12 敌而 PA-1 是 19）—— 贴上去就是两只手抢一台模拟器。

## 6. 打关主循环（编排 → 尝试 → 判定 → 归因 → 改招）

1. **编排**（离线）：`tools/stage_value.py` 出地图/波次/敌我数值 → `tools/derive_plan.py` 出站位/朝向/分工。

1. **判战斗不能用"手牌 ≥4 张"**（`annotate_view` 的旧口径）—— 在肉鸽战斗帧上**恒不成立**：
