## 我们现在的做法（是**手推的近似**，不是抄 MAA 的）

`services/ai_agent/tile_map.py::Level.project()` 是照 MAA 的数据自己推的：

```python
X = col - (width - 1) / 2.0
Y = (height - 1) / 2.0 - row
Z = height_type * (-0.4)          # 高台在屏幕上被抬高
cam = view[1 if side else 0]
x, y, z = X - cam[0], Y - cam[1], Z - cam[2]
pitch = radians(30.0)             # ← 这两个角度是我们**猜**的
if side: y, z = ...radians(10.0)...   # ← 侧视（部署终点表）用一个 10° 预旋转近似
```

**这个近似在 9×7 上刚好对上了** ✓，所以我们一直以为它对 —— 直到在 10×8 上整个崩掉 ✗。

# 更新：拿到 `TileCalc2.hpp` 后的结论（2026-09-19 晚）

感谢指路 —— `TileCalc2.hpp` 在 **`3rdparty/include/Arknights-Tile-Pos/`** ✓（我们漏搜了 `3rdparty/` ✗）。
我们已**逐行复刻**（含完整 `proj @ matrixX @ matrixY @ translate`、齐次除法、`(r+1)/2` 映射、
`ratio=720/1280`、`fov_2_y=20°`、near/far `0.3/1000`、16:9→4:3 的 `pos_adj` 项），结果：

| | 我们的旧近似 | **官方 TileCalc2 复刻** | 游戏实际（高亮量出） |
|---|---|---|---|
| PA-1（9×7, normal） | (328,110) 列基(84,22) | **(328,110) 列基(84,22)** ✓✓ 分毫不差 | 约 86×62（1280 系）✓ 一致 |
| PA-5（10×8, normal） | (320,102) 列基(**71,0**) ✗ | **(320,102) 列基(71,0)** ✗ 一样 | 约 113×103（1280 系）✗ 不一致 |
| PA-5（side=true，部署用） | — | (412,154) 列基(61,−7) 行基(2,66) | 同上 |

⇒ **两点结论**：

1. **我们的投影数学与官方完全等价** ✓✓ —— 差 2.4 倍/方向不对**不是我们实现的问题** ✗（顺带更正我们正文里那句猜测：
   **不是奇偶尺寸的问题** ✓，官方 `get_tile_world_pos` 我们已经逐项对上 ✓）。
2. **PA-5 的 `view` 数据与游戏实际渲染对不上** ✗：
   数据 `view[0] = [0.0, -6.6, -10.63]` ⇒ **cam.x = 0、yaw = 0** ⇒ 列方向在数学上**必然水平** ✓（(71,0) ✓）；
   而游戏画面上这一关的格子是**斜的** ✓，格距也对不上（差约 1.6 倍 ✗）。
