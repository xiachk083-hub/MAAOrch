### 6.2 一个重要的"懂就做、不懂就停"实例

终端页上让它"进入关卡选择页"，模型回了：

> 当前终端页的可定位元素中没有进入关卡选择页所需的"作战/关卡入口"候选，无法安全操作。（confidence 0.95）

这是**设计要的行为**：不明白就停下要人教，而不是瞎点。随后用 `discover` 扫出 `TerminalDefault` 等锚点补齐了地图。

### 6.3 踩坑与修复（真机才有）

1. **手工猜的锚点会把 AI 带沟里**：我按字面把 MAA 任务 `Fight` 当成"主界面作战按钮"，实际它的模板是 `SwitchTheme@ToggleSettingsMenu.png`（**装扮齿轮**）——LLM 信了这个锚点就点进了首页装扮模式，整屏按钮全不响应。→ 锚点必须来自**验证过的发现**或人工实测标定，不能凭名字假设语义。
2. **主题类任务（UiTheme 机制）的锚点规格必须自包含**：`{"task": "TerminalDefault"}` 解析不出来（这类任务定义里没有 template，模板由主题运行时决定）→ 发现机制改为输出 `{"template": ..., "roi": ...}`。
3. **点击后验证必须轮询**：0.5s 单次快照对"页面切换"是错的判定（主界面→终端要 ~1s），实测"点成功了却报失败"。默认等待改 1.1s + 验证轮询 6s。
4. **LLM 会把锚点"名称"当模板名填**：描述里必须给出可原样复制的规格 JSON，并加名称→规格归一化兜底。
5. **推理型模型会把 token 吃在 reasoning 上**：`deepseek-v4-pro` 每十几次就返回空 content → 空内容自动加倍预算重试一次。
6. **模拟器刚启动时设备没连到 adb server**：`AdbScreen` 补 `ensure_connected()`（MAA 也是先 connect 再操作）。

### 6.4 需要人配合的点（当前阻塞）

## 7. 真机实战记录（2026-09-14 深夜：第一次自己走到关卡并尝试开战）

### 7.1 agent 自己走完的路

`主界面` →（LLM+视觉）点终端卡片 → `终端页` →（视觉）点「离解复合」主题卡 → 章节开放弹窗 →（视觉）点「开启旅途」 → `关卡详情页 → 不可刷（代理锁定）`（15-11 一段长梦将醒，未通关无代理）→ 点「演习」（**视觉定位，禁词约束阻止了误点开始行动**）→ `编队页` → 点蓝色开始按钮（演习模式）→ 战前剧情 → 逐页跳过 → **网络掉线** → 标题页 → 点「开始唤醒」→ 回到 `主界面`。

全程无需人手干预；每步都落 `logs/agent/<会话>/steps.jsonl` + 前后截图。

### 7.2 新学到的七个事实（都已落成代码）

1. **演习（drill）只在关卡详情页，不在编队页**：详情页有「演习」按钮，点了照样进编队；**演习模式的开始按钮是蓝色并印 PLAN，普通模式是橙色**。演习是零理智的练兵场——第一场实战应该走这条路，而不是直接花 21 理智打必输的高难关。
2. **剧情页会挡住开战**，而本地 OCR **读不出**右上角那两个小字「跳过」（OCR 给的是 `OFF`/乱码）。必须用 MAA 任务模板 `SkipThePreBattlePlot`（命中 0.94）——同一个教训在「开始行动」上已经踩过一次：**小字按钮别靠 OCR，用任务定义**。
3. **硬规则必须能被显式约束拦住**：目标里明明写着"用演习、不要点开始行动"，reflex 照样点了开始行动进了编队（理智还没扣，编队确认时才扣）。于是加了 `forbid` 参数：reflex 与 LLM 都受它约束，匹配只看结构化字段（task/ocr/template），**不看自然语言描述**——因为视觉模型会用邻近元素做位置参照（"开始行动按钮左侧的演习"），用子串匹配会误伤。
4. **视觉落点质量很好**：认出「演习」按钮 @(997,667) 置信 0.85、"右下角红色开始行动按钮（消耗 -21 理智）" @(1180,663) 置信 0.96（与本地 OCR 的 (1140,655) 是同一个按钮）、"怒号光明 ROARING FLIGHT 关卡卡片" @(715,372)。**两条独立路径互相印证**，这是"未知界面不用手工锚点"的基础。
5. **缺了两个状态**：`编队页`（用 MAA `BattleQuickFormation` 模板判，1.00）与 `剧情页（可跳过）`（用 `SkipThePreBattlePlot` 模板判）。缺它们时 agent 会以为自己在关卡列表页，后续决策全错。
6. **MAA 缺省模板规则要照抄**：任务没写 `template` 字段时默认用 `<任务名>.png`。漏了这条，`SkipThePreBattlePlot` 这类任务就定位不到。
7. **模拟器网络会掉**：掉线后回到标题页，但**登录态保留**（"玩家 189****9036 / ID 751737728"），点「开始唤醒」即可回到主界面。掉线弹窗用 `OfflineConfirm` 模板定位（1.00）点掉。

## 9. 根因找到：登录认证失效（2026-09-14 深夜）

今晚四次"掉线→回标题页"的真实原因不是网络，是游戏弹的
**「登录认证已失效，请重新登录」** —— **同一账号在别处登录把会话顶掉了**。
证据：`logs/agent/td_selected.png`（点击定位那个弹窗）。

两个由此发现并修掉的缺陷：

1. **模糊掉的战斗背景让弹窗被误判成「战斗中」**：那个弹窗背后是虚化的战斗画面，
   `PRTS1` 模板照样命中 0.99 → 分类器判"战斗中" → 硬规则说"战斗进行中，等待"，
   于是 agent 老老实实瞎点了一整轮。现在加了**暗色遮罩检测**：偏暗像素占比
   > 0.66 就判"疑似弹窗遮罩（原本判为 X）"，不再按原状态行动，交给视觉确认。
   实测分离度：弹窗帧 0.744 vs 正常战斗 0.54-0.56。
2. **缺"登录失效"这个状态**：本地 OCR 读不出那个弹窗的文字（试过检测框/放大/多种
   ROI 都不行），所以状态识别走不通；现在改为"遮罩检测 + 视觉确认"，并且 reflex
   在识别到登录失效时**立即停手并说明原因**，而不是继续操作。

**给用户的结论**：这台练习机需要一个**专用账号**（或确保别处不再登同一个号），
否则任何长流程都会在几分钟内被顶掉 —— 今晚的部署测试就是这样作废的。

重测时要一次判定三件事：拖拽用 `adb input swipe` 还是需要 `input motionevent`

### 13.1 自动编队为什么失败（2026-09-14 收尾结论）

三次跑作业都复现同一条错误：

```
get_char_allocation_for_each_group has no feasible solution
asst::BattleProcessTask::to_group Group not found in combat data: 玛露西尔 / 凛御银灰 / …
```

而账号仓库核对过**这些干员全都有而且练度达标**（棘刺 精二90、桃金娘 精二40、黍 精二60、
艾雅法拉 精二90、纯烬艾雅法拉 精二90）。所以不是"缺干员"，而是 MAA 的自动编队
**没把这些人选进编队**。MAA 官方文档给了两个前提：

1. **「特别关注」的干员会被自动编队跳过** —— 需要在这几个干员的详情页取消特别关注。
2. **抄作业要求帧率 ≥60 且稳定**，低了拖拽部署会失手（我们两次都是 86 秒就输，符合这一特征）。

**机制层面搞清楚了**（从 MaaCore.dll 的字符串簇）：那条报错来自
`asst::BattleProcessTask::_run`，它用 **DLX 精确覆盖模型**把作业里的"组名"（奶盾/输出/奶）
映射到**当前编队里的干员**；建不出可行解就把该组的所有部署指令**静默跳过** ——
这就是"进战斗后一个动作都没有、86 秒就输"的直接原因。
（同一簇还有 `update deployment failed`、`Group not found in combat data:` 两个旁证。）

**绕开方案（推荐，只需一次游戏内动作）**：在游戏里把某个编队预设（例如第 4 位）设成
作业需要的那几个人，然后用 `--formation-index 4` 指定用它：

```bash
python tools/maa_copilot_run.py --emu 1 --copilot data/copilot/15-11_50051.json        --touch maatouch --no-startup --formation-index 4
```

这样**跳过自动编队**，也就绕开了"特别关注"的坑。

## 15. 多作业模式（UseCopilotList）说明 — 从 MAA 界面文案取的真值

MAA GUI 的自动战斗页有「多作业模式」开关（`UseCopilotList`），对应 MaaCore 的
`copilot_list` 参数（一组作业文件）。MAA 自己的帮助原文（从 MAA.dll 提取）：

```
仅支持以下模式:
 1. MainStage:        同一章节内导航
 2. SideStory:        当前页面内导航（普通/EX/S 不能互跳）
 3. StoryCollection:  当前页面内导航
 4. ParadoxSimulation: 从 Operator 列表启动
请在对应界面启动，不支持跨章节导航
```

其他约束（同来源）：
- 不能混用不同类型作业；只在 `UseCopilotList` 下跑**单个**作业会被提示"不推荐，单个请直接运行"
- 启用后选择单个作业会**自动加入作业列表**（CopilotList）
- 校验项：`关卡名无效，无法导航`、`关卡名与导航名不一致，已使用导航名`、`干员名称不合法：{0}`、`未选择作业`、`存在关卡名为空的作业`

### 15.1 对我们的直接价值：它写出了自动编队的两个前提

模式 4 的尾注 + 小提示第 5 条：

> **若使用 UseCopilotList，请从 Operator 列表「等级/稀有度」筛选下启动**
> **Operator 若被标记为「特别关注」，可能影响 AutoSquad 的识别与选人**

这两条正好解释了我们今晚的失败：**不是自动编队坏了，是启动状态不对**——
391 名干员的列表里，MAA 的 AutoSquad 靠"滑动 + OCR 名字"找人，
低星/低等级的在很后面，够不到（桃金娘 4★、塞雷娅都要翻很久），
于是出现 `get_char_allocation_for_each_group has no feasible solution`
或 `reason: "Unchecked"`（如用户手动跑那次）。

**正确启动姿势**（游戏内 2 分钟）：
1. 干员列表**按等级或稀有度筛选/排序**（精二 90 那批排最前）
2. 确认作业要用的干员**没有「特别关注」标记**
3. 站在关卡详情页（右下角有【开始行动】）再启动自动战斗

### 15.2 另一种用法：一次排队多份作业

多作业模式可以把若干份作业串起来跑（同一章节/同一页面内导航），
适合"一关过了接着下一关"（如 15-11 → 15-12），或为同一关排队多份作业逐个尝试。
注意它**不支持跨章节导航**，且失败后的行为没有文档保证（实测链在错误处结束）。

### 与之前失败对比（结论修正）

之前我用 Python 直接调 C API（`append_task('Copilot', ...)`）反复失败，两个原因：
1. **`formation` 参数默认 false**（官方 `integration.html` 原文）——不传它，MAA
   **不编队**，直接拿当前编队开打 → `get_char_allocation_for_each_group has no feasible solution`
   → 所有部署指令被静默跳过 → 零动作必输。GUI 的「自动编队」就是把它置 true。
2. 作业站**查询接口返回的 content 不含 `actions`**（`get/{id}` 才有）——按查询结果落盘的
   作业是空壳，MAA 报 `invalid map<K, T> key` / 解析失败。

**所以以后一律走 GUI 这条路**（界面上的开关就是参数的真值），脚本只做
"把游戏带到正确界面"和"读日志判定"这两件事。

  右键=仅移除未激活任务**。本次用**右键清除**把重复条目清掉了。
