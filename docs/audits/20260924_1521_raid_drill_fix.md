## 0. 结论摘要（先看这三条）

1. **A｜突袭不跑演习**：`--wants 突袭` 的"演习优先"**实测不可用**（2/2 份轴 `gate3-invalid`），
   且第二份把游戏留在战斗里。按 task-15 交付说明末尾自己的预警办：**突袭默认跳过演习、直接走老的降级重试路径**；
   保留的唯一开关 `--raid-drill` **默认关**。
2. **B｜演习/真打收尾必须离开战斗**：根因是 `stage_attempt.py` 的**多个出口**里只有"漏怪掐局"那一条会退出战斗，
   其余（闸0 / 闸1 拦下 / 结果帧仍战斗 / 作业超时）都是打印一句就 `exit` ⇒ 游戏停在「演习中 + ⏸ PAUSE」⇒
   之后 **4 次导航全废**、CV-1/2/3 被队列误标 `noreach`。现在**所有出口**都过 `leave_battle()`（齿轮 → OCR 找
   「放弃行动/退出演习」→ 确认真的出来了），sweep 侧还有第二道兜底（即使跑着旧版 `stage_attempt.py` 也能救）。
3. **C｜演习只烧「演习券」**（Lead 追加口径）：新增演习券读数（**读不到 = null，不瞎猜**）、
   **券 < 需要份数 ⇒ 不演习、走老路径**（原因记 `drill_tickets_low`，**绝不许**记成 `drill_broken`）、
   以及**账本断言**：演习的读数**永远不会**被记成"已通关/首通/源石到手"（`drill` 行的 `stone` 一律抹掉）。

## 2. 根因

### A. 演习通道对**突袭**不可用（`stage_attempt --drill --raid`）

| 轴 | 结果 | 证据 |
|---|---|---|
| prts://41415 | 534s，MAA 报 `Completed`，**页面 unknown（无结算页）** ⇒ `gate3-invalid` | `_ce6/..._drill_41415.attempt.log`、`attempt_..._41415.json` |
| prts://51786 | 181s，同上；`still_battle: true`（结果帧**仍是战斗 HUD**） | `_ce6/..._drill_51786.attempt.log`、`attempt_..._51786.json` |

⇒ 2/2 份轴都拿不到"演习结算页" ⇒ `drillDecision()` 只能判 `drill_broken`（"通道整体不可用"）⇒ 退回真打。
task-15 交付说明（`runtime/reports/task15_notes.md` 末尾）**自己预警过这一条**：
"突袭（`--raid`）的演习能不能跑没实测过…若实测发现突袭演习不可用，应改成'突袭走老路径'"。
本次实测确认 ⇒ 按该建议改（A 的修法）。

### B. 收尾缺口：`stage_attempt.py` 只有**一个**出口会退出战斗

| 出口 | 旧行为 | 后果（真机已发生） |
|---|---|---|
| 闸0（开局收尾，6 轮） | 只会"结算页点中央 / 地图点节点 / 其它点中央推进" | 「演习中+⏸PAUSE」点中央没用 ⇒ 连点 5 次仍判"不在详情页"（51786 第一次） |
| 闸1 拦下 | 直接 `finish(3)` | 没有把游戏带出战斗 ⇒ 后面的重导航/下一局还会照样失败 |
| 结果帧仍战斗 HUD | 只 `say("⚠结果帧仍是战斗 HUD")` 然后 `finish(5)` | **14:57 那一屏就是这么留下的** |
| 作业超时 | `proc.kill()` + `pkill screenrecord` 后 `finish(4)` | MAA 被掐时游戏多半还在战斗里 |
| 漏怪 `--abort-on-leak` | ✅ 有 `tap_abandon()`（齿轮 → OCR「放弃行动」） | 唯一有收尾的出口（但它**不验证**是否真的退出来了） |

**根因链**：`51786` 演习把游戏留在「演习中 + PAUSE」→ 紧接着的真打 fallback 从战斗里起跑（记 `failed`，
`_settle_*.png` 为证）→ 14:58 起队列重试时 `nav_map/mt_nav` 全部失败（它们只会从地图/详情页出发）→
CV-EX-8 / CV-1 / CV-2 / CV-3 被标 `noreach`（**4 个单位、共 1 次真打白跑 + 4 次假失败**）。

### C. 「演习券」全仓库从未被读/记

`grep -rn '演习卷\|演习券\|drill_ticket'` ⇒ **0 命中**（Lead 也 grep 过）。也就是说在此之前
"演习只烧券、不烧理智"这条口径**没有任何代码在管**：券耗尽时演习会静默跑不出结论，
然后被记成"演习通道坏"（`drill_broken`）⇒ 触发限流真打 ⇒ 白烧一次理智。

## 6. 已知残留 / 风险（如实列出）

1. **券读数"尽力而为"**：若游戏 UI 在该帧不显示券数 ⇒ 永远是 `null`（照常演习，日志记 null）。
   真正的拦券发生在 `stage_attempt` 点演习后的第二次读数（读到 0 / 「不足」字样）⇒ **只在"已经点了演习"之后才拦得住**，
   也就是说"券不足"这个情况**可能多消耗 0 张券**（演习没跑起来），代价是最多一次白跑 12 分钟的演习局。**不烧理智。**
2. **`need` 取 `DRILL_TRIES`（每份轴 1 张）**：某关候选轴少于 `DRILL_TRIES` 时，理论上可能因为"券只有 1 张"
   而放弃一次本来够用的演习（保守取向：零浪费优先）。要改口径就调 `--drill-tries`。
3. **灰度兼容**：机器上若还跑着**旧版** `stage_attempt.py`（没有 `left_battle` 字段），sweep 侧靠
   `still_battle===true` 兜底收尾；旧版没有 `--leave-battle`/`--read-tickets` 时对应调用会失败，
   只打日志、不中断主流程（`readDrillTickets()` 读不到 JSON ⇒ `tickets=null` ⇒ 照常演习）。
4. **演习 3★ → 真打之间的"结算页残留"**：理论上若演习的结算页还留在屏上，真打的星数读数可能被污染。
   现有防护是闸0（结算页点掉）+ 闸1（必须看到详情页才起 MAA）+ `settleFinish` 只在真打之后读一次；
   本轮**没有**新增针对它的代码（改动最小原则），**建议 Lead 在 (1)/(2) 的真机跑里顺带看一眼**。
5. **本轮的"收尾"只在 `stage_attempt`/`event_sweep` 两条链路里**：别的入口（例如手工点、或别的工具把游戏留在战斗里）
   不在本次修复范围内 —— 但 sweep 的导航失败守卫（§3.1 #5）会在下一次导航时自动把游戏带出来。
