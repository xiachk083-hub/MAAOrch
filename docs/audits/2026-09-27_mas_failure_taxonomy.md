## 4. 巡检提示词（52b88b0ffca0）改进建议

实测缺口（09-27 04:41 轮）：`triage_error` 经 SSH 读 asst.log 超时 180s → `triage_failed` → 对 `MAA 在完成任务前退出` 的 hbz\*\*-日 判「疑似真失败」并补跑；而台账显示该号同夜已被补跑 3 次（01:01/03:12/04:43），真实定性为资源类——不该再补。建议：

1. **第一层分流改为「maa_result + history .log」轻读**：读该账号在 `E:\AUTO-MAS\history\<班次日>\<账号>\` 最新一条 `.log`，grep `本轮任务出现以下错误`/`任务出错: `——小文件、秒级、不经忙时 asst.log；命中「仅自动公招」直接判资源类剔除。
2. **triage_failed 兜底口径**：不得默认按「真失败」补跑；先走第 1 条历史日志兜底，仍无法定因 → 记 `TRIAGE_UNKNOWN` 且**不补跑**。
3. **补跑去重闸**：同账号同班次日已补跑 ≥2 次（查 `mas_rerun_state` / `runtime/mas_ledger.jsonl`）→ 停止补跑、只记录。证据：hbz\*\*-日 一夜 3 补未收敛。
4. **补跑名单过滤资源类**：命中「退出+仅自动公招」或 `recruit_confirm_failed` 的号从名单剔除，不占 8 个名额。
5. **登录类不单独立项补跑**：仅当同一班次日同类 ≥20 次（如 09-23/24/25）才升级为告警行。
6. **模拟器启动失败类**：补跑前按 VMM 进程/adb 复核实例；同实例当日 ≥3 次失败 → 不补、交人工（官-28、古茶七心红、him 均属此列）。
7. **汇报加 FAILMIX 行**：`FAILMIX=<失败码计数摘要>`（与本文件第 1 节同口径），便于逐日趋势比对；「登录类计数」不得直接当「未完成号数」。
8. **补跑复核闭环**：发车后复核至少读到该号下一条 history 记录的 maa_result（有终态才闭环），别只看「发车中」就收尾。
