## 二、🔴 新增真因：闸2「通过」的触发文本是 `类2O`

**方法**：不另写判据 —— 直接 import 仓库自己的 `tools/stage_attempt.py`（`py -3.12`，cv2 5.0.0），把它自己的 `in_battle()` 与 `_ocr_text()` 跑在该局**自己留下的 25 帧序列** `runtime/_ce6/story_JT83_JT8-3_36786_drill_seq/*.png` 上：

```
011.png INBATTLE= True  | ENEMY= '' | COST= '类2O'      ← 唯一为真的一帧，18:11:32
001–010, 012–025   INBATTLE= False | ENEMY= '' | COST= ''（017 COST='米'，无数字 ⇒ 不触发）
```

**判据代码**（`tools/stage_attempt.py:203-210`）：

```python
for rect in (BATTLE_ENEMY_RECT, BATTLE_COST_RECT):
    t = _ocr_text(img, rect).replace(" ", "")
    if re.search(r"\d+\s*/\s*\d+", t) or re.search(r"\d", t):   # ← 兜底：这块里“有任意数字”就算在战斗
        return True
```

⇒ 那个 `or re.search(r"\d", t)` 把手写兜底放得太宽：**费用框 ROI 里一个 OCR 噪声字符 `2` 就足以判「已在战斗界面」**。

**这一帧确实是编队页（看图确认，不是推断）**：011/012/024 三帧都是我亲自看过的**干员编队/选择页**（011 = 夜莺详情、12 号位「夜莺」高亮；012 = 号角；024 = 塞雷娅）—— 屏幕上**没有** ENEMY 计数、**没有**费用数字。
**时间线闭合**：闸2 日志写 `t≈48s`，`t0≈18:10:44` ⇒ 18:11:32 ＝ frame 011，而 25 帧里**只有 011 为真** ⇒ 这次「通过」百分百由这一帧贡献。

**为什么这不是罕见巧合**：25 帧里 1 帧误判（4%）。闸2 是「**任意一帧**通过即通过」⇒ 一段 90s 的跑局里误通过概率 ≈ `1-0.96^24 ≈ 62%`。**也就是说：闸2 对「没进战斗」的局基本必然误报一次**，只是闸3（`valid=false / gate3-invalid`）在后面兜住了。

## 三、影响面与修复建议

**影响**：`battle` 字段在代码里的**明文用途**是「进过战斗 ⇒ 这局确定到不了 3★ 的证据」（`tools/stage_attempt.py:808` 注释）；`tools/event_sweep.mjs` 已把**真机原 JSON** 当夹具（含 `battle: true, battle_s: 81.9` 的 CV-EX-8 那份）。⇒ 假 `battle:true` 会把「**根本没跑成**」记成「**打了、打不过**」，正是 @ark 说的「别拿它推这关难打」。目前唯一防线是闸3 的 `valid:false`；**闸2 自身不可信**。

**建议（最小改动，两条一起）**：
1. `in_battle()` 去掉 `or re.search(r"\d", t)` 兜底：费用框必须读到**干净的纯数字 token**（`^\d{1,3}$`），ENEMY 只认 `\d+\s*/\s*\d+`；OCR 噪声 `类2O` 因此直接否决。
2. 加**编队页否决**：`_ocr_text` 全屏出现「确认/清空选择/开始行动/干员培养」等编队页独有词 ⇒ 直接 False（比阈值调参稳）。
3. **夹具**：把这一帧的 ROI 文本 `类2O` 固化成用例 —— `in_battle()` 必须 False（现在会 True）；`011.png` 本身留在 `_ce6/…_seq/` 里可作回归样张。
