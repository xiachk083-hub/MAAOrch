## 3. 派发策略建议（落地清单）

### 3.1 并发与装车
- `--max 6`；波次容量 4–6 张；同波内错开资源（见 3.3）。
- 全局稳态并发 6–8；30+ 只允许「全只读、互不共享文件」场景且 lead 显式说明。
- 每波开波前 5 分钟看 `hermes kanban stats`；契约/基线类优先（被引用面最广）。

### 3.2 任务粒度
- 预算式：单卡 ≤10 分钟工具时间、≤150 调用、产出 1 份文档；超 20 分钟即拆。
- 拆分轴：按对象（脚本组 / 服务器组 / 账号段）、按数据集（1 天 / 7 天）、按章节（手册分册）。
- 反面: 全库体检 54 脚本单卡 76min+；正面: 资产普查①–⑤。

### 3.3 串行 vs 并行白名单
- **必须串行（全局互斥）**: ①任何 adb input/点屏/启停模拟器；②重启 AUTO-MAS 侧车 / MAA；③发车 / 停任务 / 改队列；④写生产配置（本板不该做）；⑤任何碰同一台 MuMu 实例的操作。**避开班次窗口：05:00–05:40、19:30–20:30**（t_bec38656 停手让车是正确姿势）。
- **可并行**: 只读取证、日志抓取、API 拉取、文档整理、模板设计、技能沉淀、静态检索（本地文件/SQLite/gh 各自独立）。
- **同资源只读注意**: 多卡同时 SSH 同一宿主时，大日志一律「远端打 tar 一次、本地解包」（`hist_0926.tar` 做法正确），不要 N 次 ssh 逐文件读。

### 3.4 防重复 / 防漂移
- 建卡查重 + `idempotency_key`；发波前列一遍 running 标题。
- 已完成的审计文档 = 事实基线：新卡序言引用即可，禁止让新 worker 重推（chain.md 被读 10 次是正面信号，保持）。

### 3.5 等待类任务（事件驱动）
- 班次验收 / 闸门卡从「常驻 worker + sleep」改为「cron / scheduled 卡 + 时间点唤醒」；worker 内只允许 ≤60s 短等。
- blocked 卡必须写清「在等谁 / 等什么 / 怎么解」，让 lead 一眼可断（今天 2 张 blocked 属正常等待，但要明示）。
