## 1. 改动清单（逐项：现象 → 根因 → 改法 → 验证）

### P1 工装解释器运行时解析（新增 `pick_python()` + `PYEXE`）

* **现象**：`_prime_queue3.log:7261/7280/…` 满屏 `ModuleNotFoundError: No module named 'cv2'`；每跑一关就多一个假 noreach（14:36–14:37 连坏 CV 3 关）。
* **根因**：全文件 6 处 spawn 用**裸 `python`**，它继承调用方 PATH；PATH 上的 `python` 是**没有 opencv 的 venv**（实测：`/c/Users/xiach/AppData/Local/hermes/hermes-agent/venv/.../python` → `cv2` 不存在；Python312 → `cv2 5.0.0`）。
* **改法**：
  * 新增 `PY_PROBE = "import cv2, rapidocr_onnxruntime"`、`pick_python()`（L496）、`PYEXE = pick_python()`（L539）。候选顺序按审计指定：`$MAAORCH_PYTHON` → `sys.executable` → `shutil.which("python")` → `shutil.which("python3")` → `Python312 绝对路径`；**每个都现场 import 实测**（不是猜路径）。全都不行 ⇒ `raise SystemExit(...)`，**宁可整轮不动**。
  * 6 处 spawn 全部换成 `PYEXE`：`L563`(scan_map_panels)、`L698`(main_nav)、`L924`(discover_stages)、`L944`(enter_by_template)、`L959`(enter_event)、`L1268`(stage_attempt)。`grep -n '"python"' runtime/_prime_queue3.py` 现在只剩候选列表里那一处。
* **⚠ 与审计 diff 的**一处有意偏差**（请 Lead 知悉）：审计建议"`$MAAORCH_PYTHON` 指到坏解释器 ⇒ 必须 SystemExit"。我实现成**大声告警 + 回落下一个候选**，只有"所有候选都不行"才 SystemExit —— 理由：无人值守队列不该因为一个过期环境变量整轮不动，而"能 import cv2 的另一个解释器"与它等价安全。**想强制 SystemExit 的话删掉回落即可**（`pick_python` 里 3 行）。
* **验证**：见 §2.1（`PYEXE` 实测可 import）/ §2.2 断言 P1（含"坏 `MAAORCH_PYTHON` ⇒ 告警并回落"的子进程实验）。

### P2 工装崩溃 ≠ 导航失败（新分类 `toolcrash` + 4 处整轮中止）

* **现象**：14:36 那 3 条"导航失败 ⇒ 标 noreach"其实是 cv2 崩溃；`classify_report()` 把任何 `action=blocked` 一律翻成 `renav`，主循环随即写 noreach。

* **改法**：

  * `classify_report()` 在 `act = ...` **之前**判账本正文（`json.dumps(rec)`）⇒ 返回 `("toolcrash", rec)`；`classify()` 追加 stdout 兜底（账本都没写出来时也能认出）。
  * 主循环 4 个中止点，全部 `raise SystemExit(2)` 且**在写任何状态之前**：① 活动 sweep（L1342）② 主线导航（L1232）③ 主线真打/演习 `stage_attempt`（L1291）④ 进活动工具（L1310）。`run_enter()` 现在返回 `(ok, 原始输出)` 供判断（L944）。
* **验证**：§2.2 P2 断言 + **端到端场景 1**（造一本"fake ledger 里带 cv2 Traceback"的账本跑真 `main()`：exit=2，`_prime_state3.json` 全 `todo`、**零 noreach**）。
* **真机复现配方**（给 Lead，安全、不花理智、不改状态）：`MAAORCH_PYTHON=C:\nope\python.exe python runtime/_prime_queue3.py --max-attempts 1`
