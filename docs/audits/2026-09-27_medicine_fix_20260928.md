## 1. 方案（Phase 1 · 只读）

**问题**（审计 §3）：46 个 SR-* 账号的关卡计划为闭幕后不开放的单一活动关（`[SR-x]`），
MAA 在计划列表里选不到「当日开放」的关卡 ⇒ `关卡计划内没有当日开放的关卡` →
`理智作战 任务跳过` ⇒ **临期理智药没有任何消耗路径**（主战斗被整体跳过）。

**受影响集合（实测 46 个）**：`StageMode=Fixed 且 Stage∈{SR-7×40, SR-8×3, SR-5×3}`；
全部 `Stage_1..3 = -/-/-`（回退位是空槽）。

**修法（三选一 → b「加回退位」）**：`Info.Stage_1 := "1-7"`（单回退位即充分）：

1. **机制**：MAA 在 `[SR-x, 1-7]` 多候选里选第一个「当日开放」的关卡；`1-7` 全周恒开放。
2. **反证在案**：界内已有 `["AT-4","1-7"] → 1-7`、`["SR-7","1-7"] → SR-7`（9/08 潮响）两例。
3. **与用户惯例一致**：用户表单模式本就是 `[活动关…, 1-7]`；46 号 `Stage_Remain` 本来就是 `1-7`。
4. **不选 a（改主值为 CE-6 等）**：CE-6 周三/五不开放（9/02、9/04 实机日志），且各号刷取物偏好不一，批量替用户选择属越权。
5. **不选 c（挂计划表）**：牵动计划机制与其它使用者，回滚面大。
6. **Stage 主值不动**：保留 SR-x ⇒ 活动复刻/下一期同前缀活动自动恢复。

**改动落点**：AUTO-MAS REST `POST /api/scripts/user/update`（等价界面操作；`ConfigBase.update()` 字段级合并，
`app/models/ConfigBase.py:995`）——**只动 `Info.Stage_1` 一个字段**，不动账号/凭据/队列/计划表。

**影响面**：46 号 × 此后每轮理智（主战斗恢复即恢复临期药窗口消耗；`MedicineExpireDays=2`/48h 不变）。

**回滚**：见 §6。

**两个机制实锤（本轮新增，影响「变更窗口」重启）**：

1. **落盘语义**：`user/update` 只改内存；磁盘持久化发生于**任一 MAA 任务轮末**——
   `app/task/MAA/manager.py:210 → Config.ScriptConfig.save()`（**全文件保存**，本轮 00:22:34 的保存即写入了全部 45 个账号的变更）。
2. **不会回滚空闲期变更**：轮起快照（`manager.py:125-128` `lock()` + `UserData.toDict()` 深拷贝）只覆盖**正在运行的那个脚本**；
   API 的锁定（`配置已锁定`）恰好挡住运行中写入 ⇒ 空闲期写入在轮末保存时**保留**（45 号实锤）。
   ⚠ **重启侧车的变更窗口必须先确认落盘位**（或至少跑过一轮），否则把只存在于内存的变更丢回旧值。
