## 3. 假阳性专项：**没有假阳性**（全库 OCR 复核 51/51 通过）

用户点名要查"非地图页会不会被误判成活动地图"。做法不是抽查几张，而是**全库用 OCR 交叉验证**：

> 判据：活动地图上必然有**带本活动代号的关卡名条**（`PV-EX-2` / `MT-9` / `EA-1`…）。
> 把判成「活动地图」的每一张都全屏 OCR，看能不能读出活动代号。
> 读出 ⇒ 支持 TP；读不出 ⇒ FP 嫌疑，我再人工看图。

**结果：51/51 全部读到了本活动代号，FP 嫌疑 0 张。**

中途我犯过一个错并纠正了：第一版正则用了 `\b` 词边界，而 OCR 会把标签和代号连写成
`OPERATIONPV-2`，导致 35 张被误报成"FP 嫌疑"。改成按已知前缀锚定后全部通过。
**这条弯路本身就是"别只听判据、要验证判据"的例子。**

数值上的负向证据（`_audit_threshold.txt`）：非地图页上**任何**活动地图模板最高只到
**0.794**（`_map_mt` / `_navmt2` / `_way3`，且这些都是**真地图**），没有一个非地图页越过 0.80。
搜索"板块/全屏"界面上模板只到 **0.644**（`_verify`）。

## 4. 阈值与余量规则：**维持 0.80 / 0.06 不动**（有理由）

我对**全部 451–466 张**跑了阈值/模板敏感性（`_audit_fix2.txt`）：

```
FULL_TH=0.80 ⇒ 活动地图 45 张      整屏模板单独提到 0.90 / 0.93 ⇒ 仍然 45 张，判定一张没变
FULL_TH=0.95 ⇒ 活动地图 45 张      只有提到 0.97 才掉到 44 张
map_PV 换成"去掉通用按钮行"版本 ⇒ 判定同样一张没变
```

结论：**这两个参数在当前语料上是"惰性"的** —— 干活的是 margin 规则，不是 0.80 这个数。
所以我**没有**按"加大阈值/加大 margin"去动它：实测提阈值换不来任何收益，只会开始丢真地图。

## 5. 为什么"判成活动地图"里混着关卡详情面板

`_bk.png`、`_dlg5.png`、`_mt9.png` 这些**面板页**，OCR 能读出 5~8 个关卡代号，
因为它们就是**面板盖在活动地图上**，地图和名条从面板底下露出来（我看图确认）。
所以 `page_of` 有时会先认出"地图"再靠 margin 规则纠正成"关卡详情"。
实测纠正是对的、margin 很宽（面板页 关卡详情 0.977~1.000 vs 活动地图 0.32~0.65，
唯一较窄的是 `_verify.png`：0.980 vs 0.646，margin 0.334，仍然安全）。

⇒ **含义**：`page_of` 的"活动地图"读数本质是在认**背景图**，不是在认**前景 UI**。
面板页与地图页共用同一张背景 ⇒ 两者天生互相干扰。**这不是本次修复引入的，是这套判据的结构性弱点**，
记在这里，供后续换成"前景结构判据"（如 `stage_boxes.white_boxes` + 代号 OCR）时参考。

### 关于基线：一个必须记录的设计教训

我第一版基线只按**文件名**比对，结果现场工具一截新图就报一堆"判定变化"——
因为 `runtime/_*.png` 是**会被反复覆写的临时截图**（同名不同画面）。
比如 `_lobby3.png` 从我基线时的"手游首页"被覆写成"终端页"，于是被判成"回归"。
**改成按内容比对**（记 `sha256` 前 16 位）后：
`sha` 相同而判定不同 ⇒ **真回归**（失败）；`sha` 不同 ⇒ 只是换图（不算失败）。
现在报告会分别列出"真回归 / 换图 / 新图"，避免噪声埋掉真信号。

## 9. 未决问题（按严重度）

1. **【最高】常驻服务没重载，修复可能还没生效。**
   服务 PID 35200 是 `11:26` 前启动的；`pages_load()` 把模板缓存在 `_PAGES` 里、
   且服务不会自动重载代码 ⇒ **进程内很可能仍是旧的模板清单**（`/health` 现在还是通的）。
   用户需要按自己的节奏重启服务（前台 `python tools/maaorch_service.py --port 8765`）。
   **我没有重启、也没有杀进程** —— 队列里还有 `stage_attempt.py` 在跑，不该由审计动生产。
2. **【高】逐屏模板导致真·假阴性，会随新活动/新视图复发**（§4）。
   治本方向：别用"某活动的整屏截图"当模板，改用**前景结构判据**
   （`stage_boxes.white_boxes` 找白名条 → 只 OCR 名条 → 必须读出本活动代号），
   这条路已经在 `enter_by_template.py::looks_like_map()` 里验证过有效，应当上移进 `page_of`。
3. **【中】`map_PV.png` 是"脆弱模板"，含两处污染**：
   它裁的是 `(700,565)-(1280,700)` 的**子区域选择按钮行**（"四幕汇演/EX 彩车游行/荒芜之舞"）——
   ① 这是**所有活动地图共用**的 UI 行（换活动就变），不是判别特征；
   ② 裁图时把**鼠标手型指针**一起裁了进去。
   实测真地图 0.83~1.00 vs 非地图页最高 0.83~0.87，**间距只有 0.12，没有余量**。
   本次没改它（改了实测一张判定都不变，属无收益改动），但它是**下一条假阳性最可能的来源**，
   建议重裁。
4. **【中】代码运行态与磁盘态不一致**：审计期间 `maaorch_service.py` 被并行修改、
   `map_CV.png` 被加入、若干运行截图被覆写。我的所有数字都标注了采样时点，
