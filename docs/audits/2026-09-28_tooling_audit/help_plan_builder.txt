刷取计划生成器：干员+仓库+能力台账+活动 -> 计划草案（.md 人读 + .json=run profile 可直接执行）

options:
  -h, --help            show this help message and exit
  --account ACCOUNT     账号名（runtime/reports/accounts/<账号>/ 必须有识别产物）
  --script SCRIPT       脚本名/uid（默认自动解析：REST > 名册快照）
  --materials MATERIALS
                        只排这些材料（逗号分隔，默认=水位表全部）
  --material 材料=目标量     改单材料水位（可重复；显式指定会强制进入计划）
  --sanity SANITY       当前理智（可选；上号识别产物里没有理智，缺省只给预算估算）
  --medicine MEDICINE   本轮吃药瓶数（默认 0=不吃；写 MedicineNumb）
  --series {0,1,2,3,4,5,6,-1}
                        连战倍数（缺省不写该键，沿用该号当期值）
  --restore-after RESTORE_AFTER
                        run profile 等待策略：run_end | timeout:Ns（默认 run_end）
  --keep-remain/--no-keep-remain
                        保留该号「剩余理智」条目（默认保留：true=复制当日值）
  --prefer {best,proven}
                        选关策略：best=最优效率（默认，unknown 也排并标注）；proven=只用台账已证的关
  --no-tail-1-7         不补 1-7 尾位兜底（默认补：恒开放，只在候选全不可用时才轮到它）
  --events-warn-age EVENTS_WARN_AGE
                        活动快照超过 N 天告警（默认 3）
  --events-fail-age EVENTS_FAIL_AGE
                        活动快照超过 N 天拒绝据此判断（默认 7）
  --skip-capability     不读能力台账（不推荐：failed 关不会被剔除）
  --no-rest             不碰 REST（只离线解析脚本名）
  --rest-timeout REST_TIMEOUT
                        REST 单次超时秒
  --out-dir OUT_DIR     输出目录（默认 runtime/reports/plans）
  --list-accounts       列出已有识别产物的账号
  --selftest            离线自测（假数据；零触网、零写 runtime）
  --json                机读输出（单行 JSON）
  --exec-dry-run        生成后调 mas_run_profile.py 走 dry-run（零写）
  --exec-preflight      --exec-dry-run 时顺带让它跑一次 preflight（只读）
  --apply               真发车：调 mas_run_profile.py --apply（需用户/lead 批准）
  --disable-others      转发：单号发车时临时停用同脚本其它启用号
  --all-accounts        转发：接受整脚本跑
  --write-mode {plan,fixed}
                        转发：run profile 的写路线
  --max-wait-seconds MAX_WAIT_SECONDS
                        转发：restore_after=run_end 的等待上限
