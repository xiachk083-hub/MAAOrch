## 四、MAA 侧踩过的坑（每条都有实测对照）

1. **代理指挥必须手动取消**。开着时点「开始行动」进入的编队页是**锁的**（底部显示「本次行动配置不可更改」），MAA 的自动编队改不动 ⇒ `update_deployment` 空转 60 秒后失败。
   - 开关位置 device **(1067,591)**（点偏 25px 落在边缘 = 什么都不发生 ✗，我因此误判两次）。
   - **判据别用灰度阈值** ✗（会骗人）：可靠判据 = 与参考图的相似度（`runtime/_ce6/tpl_prts_on.png` / `tpl_prts_off.png`）；功能判据 = 进编队页看有没有那条「配置不可更改」。
2. **MAA 的 copilot 不做关卡导航**。它要求游戏**已经停在关卡详情页**（否则唯一动作是 `BattleStartAll` 反复点开始行动然后失败）。
   从大厅过去的路：作战页底部「资源收集」(531,670) → 「货物运送」(430,400) → CE-6 节点 (1020,170)。
   ⚠️ **别用「前往上一次作战」卡**：它指向"最后一次作战"，实测把我们带去过 PR-C 地图 ✗。
3. **取帧速度是真瓶颈**：默认 adb screencap ~250-380ms/帧 ⇒ MAA 第一次部署落在开打 **+13~23 秒**（首敌 3.2 秒就到）⇒ 开局必漏。
   修法：`runtime/maa_cli/config/profiles/ce6.toml` 里 `[instance_options] touch_mode = "MaaFwAdb"`（MAA 自述 "use MaaFramework ADB controller for emulator extras support"）⇒ 实测第一次部署压到 **+3 秒** ✓。
4. **`--dry-run` 只解析配置、不加载资源** ⇒ 它报的 Tile-Pos 错是假信号 ✗（别被带偏）；但它能做 schema 校验 ✓（能查出 `doc.details` 必填之类）。
5. **`maa-cli startup Official -p ce6 --batch` 是唯一稳定的"已知状态"**（大厅）✓ —— 但游戏停在干员详情页时它**静默无效** ✗，那种情况要 `am force-stop` 强杀重拉。
6. 别把 `yes` 灌进交互式命令 ✗（`maa-cli init` 被刷出 614MB 日志 ✗）。

## 五、作业格式（这里是失败最多的地方，务必按这个写）

**可用的最小骨架**（`data/copilot/CE-6_ours_v18.json` 就是它）：

```json
{
  "stage_name": "wk_melee_6",
  "minimum_required": "v4.0.0",
  "doc": {"title": "...", "details": "..."},
  "opers": [],
  "groups": [
    {"name": "左路重岳", "opers": [{"name": "重岳", "skill": 3, "skill_usage": 1}]}
  ],
  "actions": [
    {"type": "SpeedUp"},
    {"type": "Deploy", "name": "左路重岳", "location": [2, 2], "direction": "Right"},
    {"type": "SkillDaemon"}
  ]
}
```

格式规则（每条都是踩出来的）：
- **`location` 是 Tile-Pos 坐标 `[x, y]`，y 自上而下**（实测 4220 个真作业落点：直接读 **99.5%** 落在可部署格，上下翻转后只有 74.5%）。
- **组名写成「位置+人名」、每组只放一个人** ✓（v2/v6/v11/v19 都成立）。短组名（`中路`/`左后`/`P0`）会让 MAA 编队**整片报 `Missing`** ✗（v13~v18 连续六局这样挂）。
- 🔴 **`"skill": 3` 和 `requirements` 块不能同时写**：会被 MaaCore **拒收**（`MaaCore returned an error`，加载即失败）。去掉任一个就能加载 ✓。**当前作业因此不带 `requirements`**。
- **不写 `requirements` 时，某些干员会被判 `OperatorMissing`** ✗（单人对照：**同一个乌尔比安**，加上 `requirements` 就编成、不加就判找不到 —— 所以这个字段在左右 MAA 的行为）。但**别乱写**：给所有条目写 `elite:0, level:1, module:0` 会把**装了模组的塞雷娅**顶掉 ✗。稳妥写法（若要用）：`elite`/`level` 取 box 真值、`skill_level` 给最低值、**`module`/`potential` 不要写**。
- **MAA 编队是「候选缺失就顺延下一个」** ✓（不是随机挑人）：给它一串候选，缺了会自动往下选。
- 三星必须**零漏** ⇒ 部署顺序按首达时刻排（最早那路先下）。
- ✅ **作业格式本身没问题、能加载**（实测 ✓ `--tag v34` 直跑 MaaCore 54 秒、走到编队）：
  `stage_name` / `location` / `direction` / `groups` / `actions` 全按上面写就对了 —— 卡住的是**编队**，不是格式。
- 🔴 **`--formation`（自动编队）是当前真正的墙**（详见第八节）：v18 的 6 个组，MAA 只编进
  重岳 / 玛恩纳 / 乌尔比安 / 闪灵 4 个 **✓**，桃金娘 + 仇白 报 `reason=Missing` **✗**（实测 ✓）。
  编队失败发生在**开打前** ⇒ **不花理智** ✓，所以换人/换组名可以随便试。
