> 单文件契约：席位 / 设备 / 消息 / 汇报。**本文件是协作规则的唯一入口**；群里历史消息里的口头硬线（"03:43 硬线"这类一次性条款）一律作废，冲突以本文件为准。

## 0. 三句总则

1. **一台设备，一个占用者**（默认 = 队列/启动器；其他席位是借用的客人）。
2. **一个事实只说一次**（谁先说算谁的；别人引用而不重述）。
3. **一个状态只有一个出口**：`tools/fleet_status.py`（只读一屏）+ 群里的结果通报。

## 2. 设备契约（唯一通道，别的都作废）

1. 要用设备 → `touch runtime/_preempt.flag`，并写 `runtime/_device_want.txt`：`谁 | 要多久 | 死线 HH:MM | 理由`。
2. 队列在**单位边界**优雅退出（日志打 `==== 让位`，状态落盘）；启动器即使再拉起队列，见到 flag 会秒退、不碰设备。
3. 用完 → `rm` flag + 群里一行通报：`[设备归还] 谁、做了什么、耗时`。
4. 续跑由 owner（PRTS）负责并在群里公告重启时间；断路器停了就手拉。
5. 紧急（死线 <15 分钟）→ owner 直接 kill 让位，**不需要用户点头**；这是唯一例外通道。

禁止：新造 flag/锁/**新的**看门狗、长轮询设备、绕过队列直接开 MAA、未经 owner 重启。
> 例外：§2.5 紧急 kill 通道的**唯一**自动化实现 = owner 维护的 `runtime/_watch_preempt.sh`（它是该通道本体，不算"新看门狗"；要改就改它，别再起第二个）。

## 3. 消息纪律（治"晚到旧消息"）

- **状态/进展 → 群**；**直接行动指令 → DM**。同一件事不两边各说一遍。
- **行动类 DM 必须带 `[TTL HH:MM]`**。过期的消息只有一种待遇：**已过期，忽略**（不整理、不回复、不"收尾"）。
- 收到晚到的旧消息：先看 TTL/时间戳，过期直接丢；不确定且会阻断当前任务的，问发送方一句（一句话，不展开）。
- 禁止在群里积累一次性规则/硬线；新问题 → 改本文件的一般条款。

## 4. 汇报格式（谁在等谁）

- 阻塞通报三件套：`等 X｜阻塞于 Y｜死线 Z`（一行，进群）。
- 谁都不许静默等待；也谁都不许为"等"发第二条。
- 状态自查：`python tools/fleet_status.py`（只读，不碰设备不写文件）。
