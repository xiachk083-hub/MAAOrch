# 增量挖矿策略（用户 2026-09-24 提出）

**要求原话**：如果有别人拿这套去打自己的号，不能让他"先把所有东西扫一遍"才能开工。
**找到一个能挖的，就先打**；进去之后后面实在打不过，再去找别的。

## 一、原则：先干活，边干边建图

| ❌ 全量前置 | ✅ 增量贪心（本项目的做法） |
|---|---|
| 先扫完整页网格 → 建全部卡片模板 → 排产 → 再开打 | **找一个就开打**：进第一个到手的活动 → 问一次视觉模型拿它这一屏的关卡与坐标（~17s）→ 从**最便宜/最可能三星**的关开始 → 打不过就换下一个 |
| 新号第一次要等几十秒到几分钟 | 新号第一次 **~1 分钟**内就能开打 |

## 二、具体规则（写死在流程里）

1. **入口不做全扫**：`enter_by_template` 只扫到**第一张命中的卡**就点进去（不是扫完全页）。
2. **单图建库**：进图后 `tools/learn_map.py` 问一次视觉模型 → `runtime/learned/nodes_<前缀>.json`
   （关卡代号 + 白框中心坐标）；**只建当前这张图的库**，别的图等用到了再说。
3. **由易到难**：同一活动内先打**主区**（apCost 低、机制简单），EX 解锁后再打 EX，突袭放最后。
4. **卡住就换**：某关连续 N 次没过（含"三份轴都不行"）⇒ 标记 `failed`，**立刻转下一个单位**；
   同一个活动连续 K 关都卡 ⇒ 整个活动降权，去挖别的（`plan_mines` 的 EV 排序天然支持）。
5. **随时可停**：账本 `runtime/axis_outcomes.jsonl` + 状态表 `_prime_state3.json` 落盘，
   随时中断/续跑；下一次开工从"还剩什么"继续，而不是从头扫。

## 三、对"别人的号"意味着什么

- **不需要带任何游戏内数据**（见 `docs/NO_SHIPPED_DATA.md`）：关卡清单/坐标/卡片全部运行时学；
- **不需要预热**：开局就在打，库存是打的副产物；
- **不需要配置**：账号 box 由 MAA 提供，作业轴由作业站筛，剩下的都是本地判据 + 一次视觉模型调用。

## 四、当前实现状态

| 规则 | 状态 |
