### 3.4 口径陷阱（本次踩坑，后人少走）

1. **文件 mtime ≠ 净增长**：活动实例镜像几乎全部 <1 天（`<1d` 桶 1.30 TB）；`asst.log` 每天整份计入——"DAY/mtime"表只能当**活动度**看。
2. **MuMuManager `info -v all` 偶发不全**（本次缺 idx51）——计数类结论须交叉复核。
3. **本环境 PowerShell `Get-ChildItem -Recurse` 扫大目录偶发"静默崩"**（脚本中途消失、无输出、exit 0；本次 3 次复现，同语句重跑又通过）⇒ 大目录统计改用主机自带 `C:\Program Files\Python312\python.exe`（os.walk，**并配合第 4 条的 junction 修剪**），见附录 D。
4. **旧式 junction 陷阱（本次最坑的一处，务必转告后续复测者）**：`C:\ProgramData` 下的 `Application Data`（自指）、`Documents`、`桌面`、`「开始」菜单`、`Templates` 等 legacy junction（FILE_ATTRIBUTE_REPARSE_POINT=0x2416）在 Python 3.12 下 **`DirEntry.is_symlink()` 返回 False**（注意：`os.path.islink()` 单独看反而是 True——只测 islink 会被误导）⇒ 裸 `os.walk()`（含 `followlinks=False` 默认）**仍会递归下钻**，在路径长度允许范围内把同一棵树反复重扫约 32 层 ⇒ 尺寸/文件数被灌水。实测同一目录：裸 `os.walk` = **197,577 MB**，修剪 reparse 后 = **6,174 MB**（≈6.03 GB，与 policy doc 一致；膨胀 32×）。**凡统计可能含 junction 的树（C:\Users、C:\ProgramData、C:\Documents and Settings 等）必须手动修剪**：`dn[:] = [d for d in dn if not (os.lstat(join(dp,d)).st_file_attributes & 0x400)]`。E: 盘各目录与账面对得上，无此问题；**scan.py 并行输出的 CTOP 行（Users/Windows 等）按此口径均不可引用**。
